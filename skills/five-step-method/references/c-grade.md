# C 级与超纲任务附加规程

本文件是 five-step-method 的按需加载部分。C 级任务、或任何分级下发现任务超纲时读取。

## 一、C 级完整碰撞必做四件事

1. **反问采访**：按决策树逐支下钻、一次一个问题，沿依赖关系问到底（先问会改变后续方向的问题，被前面答案排除掉的分支不再问），每问必附推荐答案
2. **备选方案**：至少给出 1 个不同于用户原始指令的方案，附取舍理由
3. **补齐边界**：列出用户没提到的——异常流、权限影响、数据兼容、回滚方式
4. **《需求简报》落盘**：写入项目内文件（同时对抗长会话上下文压缩），模板：业务目标 / 可验收成功标准 / 范围内外 / 已定关键决策 / 备选及否决理由 / 边界风险 / **尚未明确（迷雾区：当下答不了、待前置决策解锁的问题——不许硬问硬答造伪决策）**

## 二、超纲升级：任务大于单个会话时（先制图，再动工）

发现任务规模超出单个会话可承载时，**停止直接进五步，先制图**并告知用户「本任务超纲，建议先建地图」。

1. **地图文件**：五段结构——目的地 / 备注 / 已定决策（含理由与日期）/ **尚未明确（迷雾区）** / 范围外（落盘路径见主文件适配层）
2. **决策票据**：每张票据 = 一个待决策项（「要不要、怎么做」，不是代码任务），标状态与依赖。迷雾区里还问不出精确问题的部分，等前置票据解决后再「毕业」成新票据
3. **Plan, don't do**：地图完成 = 迷雾区清空、无票待决——动手前没有任何事还需先决定
4. **一会话一票据**：每会话只认领一张票据（或一期实施），完成即更新地图、结束会话；下会话从地图继承上下文，不依赖会话记忆
5. 地图内每期实施照常按分级走五步；地图更新是该期收尾动作

## 三、业务控制点（C 级实施前逐项自答，用户只对有风险的项拍板）

下列为**填空模板**——把示例项换成你自己项目的高危资产清单。AI 逐项自答并各附一句依据；用户只对答「是」或存在风险的项拍板「该后果能不能接受」。

- 是否影响现有核心业务流程 / 线上主要交易或转化路径？（示例：你的电商店铺、支付渠道）
- 是否影响数据库权限或数据结构？（示例：你的后端数据库、多租户隔离）
- 是否影响多组织 / 多项目 / 多角色的共用结构？
- 是否会新建与现有能力重复的接口 / 组件？
- 是否修改公共组件？影响面是否已列出？
- 是否触碰生产环境？回滚方案是什么？
- 哪些动作必须人工确认后才能执行？
