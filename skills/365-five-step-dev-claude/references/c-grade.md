# C 级与超纲任务附加规程

本文件是 365-five-step-dev-claude 的按需加载部分。C 级任务、或任何分级下发现任务超纲时读取。

## 一、C 级完整碰撞必做四件事

1. **反问采访**：按决策树逐支下钻、一次一个问题，沿依赖关系问到底（先问会改变后续方向的问题，被前面答案排除掉的分支不再问），每问必附推荐答案
2. **备选方案**：至少给出 1 个不同于用户原始指令的方案，附取舍理由
3. **补齐边界**：列出用户没提到的——异常流、权限影响、数据兼容、回滚方式、暴露面（这个改动会出现在谁眼前：身份 × 入口）、静默失败面（哪里会静默回退/降级/吞错？失败时谁会知道？）
4. **《需求简报》落盘**：写入项目内文件（同时对抗长会话上下文压缩），模板：业务目标 / 可验收的成功标准 / 范围内与范围外 / 已确认的关键决策 / 备选方案及否决理由 / 边界与风险清单 / 尚未明确（迷雾区：当下无法回答、待前置决策解锁的问题——不许硬问硬答产生伪决策）。简报请用户确认时固定附一个封口问：「迷雾区之外，还有没有你在意但我没问到的？」

## 二、超纲升级：任务大于单个会话时（先制图，再动工）

发现任务规模超出单个会话可承载时，**停止直接进入五步，先制图**，并向用户报告"本任务超纲，建议先建地图"。

1. **建地图文件**：`docs/maps/<任务名>.md`（项目无 docs 目录则放 `.claude/maps/`），五段结构——目的地（要抵达的业务结果）/ 备注（背景与约束）/ 已定决策（每条含理由与日期）/ **尚未明确（迷雾区）** / 范围外
2. **决策票据**：地图内维护票据清单，每张票据 = 一个待决策项（"要不要、怎么做"的问题，**不是代码任务**），标注状态（待解决/解决中/已定）与依赖（被哪张票挡住）。迷雾区里"还问不出精确问题"的部分，等前置票据解决后再"毕业"成新票据
3. **Plan, don't do**：地图完成的标志 = 迷雾区清空、无票据待决——动手实施前没有任何事还需要先决定
4. **一会话一票据**：每个会话只认领一张票据（或已定方案的一期实施），完成即更新地图、结束会话；下个会话从地图继承上下文，不依赖会话记忆
5. 地图内每期实施自身照常按分级走五步；**地图更新纳入该期 Verify 的收尾动作**（与写运行日志并列，不更新地图不算完成）

## 三、业务控制点（实施前由 AI 逐项自答并各附一句依据；用户只对答"是"或存在风险的项拍板该后果是否接受）

- 是否影响现有核心业务流程的正常运行？
- 是否影响数据库权限或数据结构？
- 是否影响多公司、多项目、多团队的共用结构？
- 是否会新建与现有 AI 接口重复的能力？
- 是否修改公共组件？影响面是否已列出？
- 是否触碰生产站点？回滚/备份方案是什么，是否已验证过内容（不能只看命令退出码）？
- 哪些动作必须人工确认后才能执行？
