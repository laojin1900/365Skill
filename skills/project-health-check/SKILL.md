# 项目健康巡检（只读）

检查用户所问的范围，区分事实、推断和未检查项；发现问题不等于获得修复授权。
单个项目存在维护中的健康技能时，先走该项目入口，不叠加本技能的第二套流程。
没有维护中的项目入口时，使用下面的有界后备流程，不猜测不存在的脚本或引用。

## 确定范围

- 单项目从当前目录或用户指定的项目开始；跨项目从明确给出的路径或应用已保存的
  项目清单选择。没有范围且无法可靠确定时，问一个范围问题；不默认递归扫描
  `$HOME`、Library、下载目录或其他无关目录。
- 用户确实请求目录发现时，只在指定根目录内有界发现，兼容 `.git` 文件与目录，
  不跟随任意符号链接。先列候选，不自动把发现的每个仓库都纳入深度检查。
- 用 Git common directory / worktree 元数据识别关联；同 remote 的独立克隆仍分别
  保留身份。新提交、目录名或最新副本都不能确立 canonical 权威。
- 提交日期不等于任务活动时间。不能仅凭几天没提交判定无主、烂尾或可删除。
  报告本次实际检查与不可达/未检查的范围，不把遗漏算作健康。

## 按问题选择检查

| 问题 | 最小事实 | 判读限制 |
| --- | --- | --- |
| 本地工作状态 | root、branch、status、实际 upstream 与 ahead/behind | 缓存 ref 不是远端实时证明；无 upstream 不是零待推 |
| 关联 worktree | common dir、列表、锁定/缺失元数据、必要的 scoped status | dirty/untracked 或旧分支可能是正常工作，不自动清理 |
| PR / CI | 对应仓库、PR head、同 workflow/branch 的运行结果与时间 | 不混算不同流水线；红灯后的新提交不等于修复验证 |
| 待续工作 | 当前模块 checkpoint 或明确相关的任务/回执 | 没有负责人信息就标未知，不读完整历史找罪证 |
| 自带健康工具 | 先检查工具的输入、读写及网络边界，再选必要命令 | 名称带 audit/health 不保证只读，不盲跑 package script |

`gh` 不可用、未认证或远端受限时，完成可用的本地检查，标明远端未验证；
不触发登录/OAuth、读取凭据或代替用户重跑 CI。需要刷新远端时先明确其必要性，
说明 fetch 会更新本地 refs；不能把缓存结果包装成已获取的最新远端。

## 输出与后续

按项目简述状态、决定性证据、负责人（或未知）、下一步和覆盖限制。
采用 `HEALTHY / ATTENTION / ACTION_REQUIRED / BLOCKED`，仅对已检查范围下结论；
缺失数据标为 `UNAVAILABLE / NOT_CHECKED`。年龄/未推提交只是背景，是否阻塞取决于
用户所问的下一步。小问题无需固定一页报告、A/B/C 分级或附完整命令输出。

- 不输出原始 remote URL、私有地址、凭据、环境文件、原始个人信息或未净化的日志。
- 不自动改文件、reset、stash、clean、删分支/worktree、创建/归档任务、ACK、改绑定、
  push、合并、重跑 CI、发布或发消息；建议不授予这些操作。
- 用户已明确要求某项修复时，转目标项目的具体实现技能，在该授权范围内继续；
  普通修复不强制五步法、另建任务或重复确认。实际受保护动作仍遵守其操作器与授权。
- 不因一次巡检自行设置定时器；已有监控按产品机制执行，状态无变化时保持安静。
