# 项目健康巡检（只读）

**状态：experimental / 早期** —— 本技能刚发布，目前仅在单个真实开发环境跑过一轮完整冒烟（发现并修复过一次路径通用化问题），检查清单的判读规则尚未经过大规模验证。使用中遇到误报/漏报，欢迎按下方反馈渠道报告。

职责：把「散落在各仓、没人认领的状态问题」收拢成一页可判读的报告。**只读不修**——任何修复动作都是新的开发需求，报分级走五步法（推荐搭配 `365-five-step-dev-claude`，非必需）。

## 巡检范围

- 自动发现：`find "$HOME" -maxdepth 3 -name .git`（排除 Library 与其他系统目录），近 14 天有提交的仓算「活跃」，逐仓巡检；扫描根目录可由用户指定，默认 `$HOME`
- **先归并再列仓**：对每个候选路径先跑 `git worktree list` 认亲——挂在别的仓下的目录是 worktree，不是独立仓，归到宿主仓那一节报（曾把一个 worktree 当独立项目报进报告）
- **活跃度一律用该目录 HEAD 的提交日期**（`git log -1`）：`git log --all -1` 在共享对象库的 worktree 上会返回全仓最新提交，让闲置 worktree 看起来很活跃
- 同一项目的多个副本（如同一仓库在多台机器/多个目录下各有一份 checkout）按 remote URL 归并，以提交最新的副本为准，其余副本只查「是否落后/有残留」
- **跳过的仓必须在报告里点名并注明原因**（不活跃 / 不可达 / gh 未认证）——静默漏检比不检更糟

## 每仓检查清单（事实 → 判读；判读规则是本技能区别于脚本的理由）

| # | 事实采集 | 判读规则（防误报） |
|---|---|---|
| 1 | CI 红灯：`gh run list --limit 10` | 连红 ≥3 才升级；**报之前先比红灯时间戳与最近相关合并的时间戳**——红灯早于修复的标「疑似已修，待下次运行确认」，不直接报障 |
| 2 | stale PR：`gh pr list --state open`，>3 天无更新 | PR 正文有 WIP/续做落点声明的算「刻意暂停」（并行协作场景下收工登记的合法产物），不算烂尾；无声明的标「无主候选」 |
| 3 | 未推工作：各分支 ahead of origin、工作区/worktree `git status --porcelain` 非空 | 区分「活跃会话正在干」（当日有动静）与「中断残留」（≥2 天无动静）——只有后者进报告 |
| 4 | 孤儿 worktree：`git worktree list` 逐个查 porcelain 与最后提交时间 | 干净且 ≥3 天无提交 = 清理候选；**只列不删**（删除需先确认工作区干净 + 知会原会话或负责人批准，推荐配合 `parallel-sessions-protocol` 的相关安全闸） |
| 5 | 项目自带健康工具（若在场）：如自定义的 stray-file 扫描脚本、CI 红灯告警 workflow | 有则跑/读输出并纳入报告；无则注明「该仓无自带工具」 |
| 6 | 五步法账本（若安装了 `365-five-step-dev-claude`）：其 `logbook.md` 未回销待验 + 最新归档末尾的「开口事项」 | 触发条件已成立的标红；未到触发时点的标灰不催；未安装该技能则跳过本项并注明 |

## 报告格式（一页，给负责人；不自动执行任何修复）

每仓一节：🔴/🟡/🟢 + 事实（原始命令输出摘录）+ 判读 + 建议动作；末尾汇总「建议立项」清单（每项一句话 + 建议分级 A/B/C）。**证据只放实拉的原始输出，推断必须标注为推断，引用数字须与来源对得上账。**

## 边界（不可越）

- 全程只读：不 push、不删分支/worktree、不改任何文件、不合并、不重跑 CI
- gh 不可用或未认证：降级为纯本地 git 检查（清单 3/4/6 仍可跑），报告开头声明降级范围
- 巡检发现的问题不在本次修：转为立项建议，负责人点头后按五步法开工
